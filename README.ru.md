# Wheel

## Начало

- Опиши, что нужно создать, заменить или расширить. Wheel ищет зрелую готовую основу до появления плана реализации.
- Вызови единственную пользовательскую точку входа:

  ```text
  /wheel self-hosted трекер задач, который могут вести ИИ-агенты
  ```

- Сначала Wheel возвращает Семейства решений и один вопрос, ответ на который меняет оставшихся Кандидатов.
- Новый код рассматривается только после проверки Ядра и подтверждения оставшегося Зазора.

## Запуск

<p align="center">
  <img src="./assets/readme/pipeline.svg" width="100%" alt="Состояния запуска Wheel: context, quick, question, deep, verify, decision и recorded.">
</p>

- Каждая Запись запуска проходит `context → quick → question → deep → verify → decision → recorded`.
- Состояние сохраняется после каждого завершённого этапа, поэтому прерванное исследование продолжается без превращения старого результата в постоянный каталог.
- Состояние `recorded` доступно только после принятия Вердикта пользователем.

## Результат Wheel

- `COMPLETE`: каждый запланированный класс Источников дал проверяемые Доказательства, а проверка Ядра пройдена.
- `PARTIAL`: хотя бы один запланированный класс Источников не дал проверяемые Доказательства; отсутствующее покрытие остаётся видимым.
- `PROVISIONAL`: обязательная проверка Ядра не завершена; окончательный Вердикт запрещён.
- `deploy`: установить проверенное Ядро без изменений.
- `package`: упаковать Ядро для целевой среды.
- `compose`: соединить Ядро с целевым Sidecar или Донором.
- `extend-core`: использовать поддерживаемую границу расширения.
- `hard-fork`: изменить Ядро и принять постоянное владение только после измерения стоимости миграции.
- `assemble`: соединить проверенные части при отсутствии прямого Ядра; режим не разрешает неподтверждённую реализацию с нуля.
- Вердикт называет Ядро, upstream или Форк, проверенную версию, Доноров, лицензионную границу, способ интеграции, отклонённые Альтернативы и отложенную работу.
- Экспертная Запись решения дополнительно несёт `evidence_gaps`: список объектов `{source, reason}`, называющий каждый источник, который ничего не вернул, был заблокирован или недоступен. Пустой список разрешён и является утверждением, что ответили все источники.

## Живое исследование

- До внешнего исследования Wheel читает текущий запрос, безопасную память хоста, проектные инструкции, существующие Записи решений и свежий снимок `doctor`.
- Быстрый проход формирует от трёх до шести Семейств до первого вопроса.
- Глубокий проход проверяет от четырёх до восьми Кандидатов и связывает их upstream, Форки, Плагины, Sidecar и Доноров.
- Репозиторные Доказательства включают метаданные GitHub, исходники, тесты, релизы, issues, discussions, contributors и лицензии.
- Трендовые Доказательства вычисляются, а не берутся из чужого рейтинга: окна `created:` и `pushed:` по GitHub API плюс движение звёзд, измеренное относительно вчерашнего опубликованного каталога.
- Сообщественные Доказательства собирает команда `community-signals`: Hacker News, Stack Overflow, Reddit и собственные issues репозитория проверяются на фразы сожаления и постмортемы. Каждый источник сообщает свой статус, а `available_sources: 0` означает, что доказательства не собраны, а не что жалоб не существует.
- Agent Reach обнаруживает и ищет страницы; управляемый DonSeTch `3.4.4` читает динамические страницы через изолированную границу CLI/JSON.
- Поисковый сниппет используется только для обнаружения. Wheel читает доступную страницу до создания Доказательства и честно сохраняет blocked, partial, truncated или thin результат.

## Ежедневный каталог

Живой запрос уже отвечает на вопрос «что существует». На вопрос «что движется»
может ответить только вчерашний снимок, и это единственная работа каталога.
Сервер для неё не нужен.

- `.github/workflows/sync-catalog.yml` запускает `scripts/build_catalog.py` по ежедневному cron и вручную. VPS не нужен: хостом выступает GitHub Actions, ключом — `GITHUB_TOKEN`, и каждое действие закреплено по коммиту. Один измеренный прогон стоит 264 запроса к API и около 200 секунд.
- Каждая запись построена из ответов GitHub API. Ничего не парсится с отрендеренной страницы, и каждая запись называет своё происхождение как `github-search:<id>` или `awesome-list:<id>`.
- Движение измеряется относительно предыдущего опубликованного каталога через `stars_delta` и `stars_per_day`. Запись без истории несёт `null`, потому что «не двигался» и «неизвестно» это разные утверждения.
- Публикуется 400 записей в четырёх слоях: 120 курируемых из awesome-списков, 60 emerging gems, 180 по измеренному движению, остальное свежий приток по звёздам, чтобы репозиторий без истории получил базу на завтра, а не оказался заперт снаружи.
- Слой gem нужен потому, что все остальные слои ранжируют по звёздам, а gem по определению то, что звёздный рейтинг ещё не нашёл: молодой, с лицензией, активно развиваемый, меньше 500 звёзд.
- Курируемые списки читаются как полноценные источники, среди них `ashishps1/awesome-system-design-resources`, `punkpeye/awesome-mcp-servers`, `hesreallyhim/awesome-claude-code`, `awesome-selfhosted` и `public-apis`.
- Оба реестра это один контракт. Сборка падает, если источник не объявил capability или объявил такой, который `registry/capabilities.yaml` не умеет классифицировать, поэтому запись, до которой никто не дотянется, не публикуется.

  ```bash
  python scripts/wheel.py sync-catalog --json
  python scripts/wheel.py search-catalog --kind mcp-server --capability mcp-servers --limit 20 --json
  python scripts/wheel.py search-catalog --moving --limit 20 --json
  python scripts/wheel.py search-catalog --query "трекер задач" --gem --json
  ```

- `--moving` возвращает только записи с измеренным движением и ранжирует их по скорости, а не по абсолютному числу звёзд. Каждый ответ несёт `age_days`, `stale`, `with_momentum`, `matched` и `truncated`, поэтому каталог целиком никогда не попадает в контекст агента.

### Второй origin

Клиент читает каталог с jsDelivr и `raw.githubusercontent.com`. Оба резолвят одну
и ту же ветку `data`, то есть переживают сбой одного CDN, но не сбой GitHub.
Независимым второй origin делает опциональный edge на Cloudflare.

- `edge/worker.js` отдаёт `catalog.jsonl` и `catalog.meta.json` из Cloudflare KV только на чтение, с ETag и ответом 304 на `If-None-Match`. `/health` сообщает время загрузки и число записей.
- Ночной воркфлоу выгружает данные через `scripts/publish_edge.py`, и шаг пропускается, пока не заданы все три секрета Cloudflare, поэтому полунастроенный репозиторий не может уронить сборку.
- Клиент предпочитает `WHEEL_CATALOG_EDGE_URL`, если эта переменная окружения задана на машине с плагином. Она валидируется как HTTPS и попадает в allowlist только этого вызова. Не задана — ничего не меняется.
- Полная инструкция по развёртыванию лежит в [edge/README.md](./edge/README.md).

## Установка

### Codex

- Добавь marketplace Wheel и установи плагин:

  ```bash
  codex plugin marketplace add kalpakprod/wheel --ref main
  codex plugin add wheel@wheel
  ```

- После обновления плагина начни новую задачу Codex, чтобы навыки и манифесты загрузились вместе.

### Prime Agent

- Установи пакет из закреплённого тега:

  ```bash
  prime-agent package install git:github.com/kalpakprod/wheel@v0.7.0
  ```

- Начни новую сессию или выполни `/reload`. Wheel разрешает путь к runtime из установленного пакета, а не из текущего каталога проекта.

### Claude Code

- Добавь marketplace и установи Wheel:

  ```text
  /plugin marketplace add kalpakprod/wheel
  /plugin install wheel@wheel
  ```

- Перезапусти сессию, чтобы необязательный SessionStart-адаптер мог выполниться.

### Совместимый CLI с SKILL.md

- Скопируй `skills/wheel/`, `skills/wheel-research/`, `skills/wheel-grilling/` и `skills/wheel-decision/` в каталог навыков CLI.
- Загрузи `skills/wheel/SKILL.md` как единственную пользовательскую точку входа.
- Хост должен поддерживать `SKILL.md`, локальные команды и Python 3.11 или новее.

## Runtime

- Runtime Python использует только стандартную библиотеку.
- Проверь хост и управляемую зависимость:

  ```bash
  python scripts/wheel.py doctor --json
  python scripts/wheel.py dependencies --json
  ```

- При первой активации устанавливается только проверенная версия DonSeTch, а upstream-метаданные проверяются через 24-часовой кэш:

  ```bash
  python scripts/wheel.py dependencies --ensure --check-latest --json
  ```

- Установи `WHEEL_NO_BOOTSTRAP=1`, чтобы отключить автоматическую установку и сохранить диагностику.
- Wheel скачивает официальный upstream asset, проверяет закреплённый SHA-256, разрешает только точный payload платформы и проверяет версию бинарника до использования.
- Более новая upstream-версия DonSeTch сообщает `update_available`; Wheel сохраняет проверенную закреплённую версию до её проверки в следующем выпуске Wheel.
- Измерь кандидата вместо доверия его README. Каждая команда сообщает статус по каждому источнику, а всё неизмеренное так и говорит, вместо того чтобы пройти как ноль:

  ```bash
  python scripts/wheel.py community-signals --slug psf/requests --json
  python scripts/wheel.py dependency-debt --slug psf/requests --json
  python scripts/wheel.py hard-metrics --slug psf/requests --json
  ```

- `hard-metrics` возвращает bus factor, индекс концентрации HHI, каденцию коммитов за 52 недели и каденцию релизов. На `psf/requests` измерено: bus factor 3, HHI 0.1572, 120 коммитов за 52 недели, 19 релизов с медианным интервалом 19.03 дня.
- `dependency-debt` возвращает транзитивное число зависимостей из GitHub SBOM, прямое число из манифестов семи экосистем и число пакетов без лицензии. На `psf/requests` измерено 6 прямых и 30 транзитивных. Если SBOM недоступен, статус `partial`, а `transitive` равен `null`.
- `community-signals` проверяет по одной фразе за раз, потому что единый запрос со всеми фразами не находит ничего на Algolia и отклоняется GitHub search. `registry/probe_terms.yaml` содержит фразы для en, ru, es, pt, de, fr, zh и ja; английский набор проверяется всегда, `WHEEL_PROBE_LANGS` добавляет остальные, а общее число ограничено восемью терминами на источник, чтобы стоимость API не взорвалась.
- Reddit использует app-only OAuth через `WHEEL_REDDIT_CLIENT_ID` и `WHEEL_REDDIT_CLIENT_SECRET`. Пользовательский аккаунт не участвует, поэтому плагин не может привести к бану аккаунта пользователя. Без учётных данных используется управляемый читатель DonSeTch, а затем честный статус `blocked`.
- Тип гранта следует типу приложения, зарегистрированного на <https://www.reddit.com/prefs/apps>: **script** и **web app** имеют секрет и аутентифицируются через `client_credentials`, **installed app** секрета не имеет и работает через `installed_client`. Неверный грант возвращает пустой 401, поэтому Wheel выбирает его по наличию секрета, а не угадывает.
- [Data API Wiki](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki) требует формат агента `<platform>:<app ID>:<version> (by /u/<username>)` и заявляет, что неопознанные клиенты ограничиваются или блокируются. Задайте `WHEEL_REDDIT_USERNAME`, и Wheel соберёт `python:com.kalpakprod.wheel:v<версия> (by /u/<ник>)`; `WHEEL_REDDIT_USER_AGENT` заменяет строку целиком. Установка, которая себя не называет, до Reddit не доходит: источник отвечает `blocked` вместо анонимного запроса.
- Опубликованный лимит: 100 запросов в минуту на один OAuth client id. Wheel читает `x-ratelimit-remaining` и `x-ratelimit-reset` из каждого ответа и отказывает в следующем вызове, когда в окне остаётся меньше пяти запросов, то есть соблюдает лимит, а не узнаёт о нём из 429.
- Пути в обход OAuth нет. Чтение того же контента через читалку страниц маскировало бы способ доступа к данным, что запрещает [Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy), поэтому без учётных данных доказательств из Reddit просто не будет.
- Ничего из Reddit не пишется на диск. Reddit требует удалять посты из любой хранимой копии, включая заголовки и вложенные ссылки, а файл решения в git этого выполнить не может. `scripts/wheel.py` отклоняет решение или запись прогона со ссылкой `reddit.com` или `redd.it`; Reddit влияет на вердикт во время прогона и указывается как источник для повторного запроса.
- Когда сам Reddit не отвечает, включается ветка `reddit-archive`: поиск по [Arctic Shift](https://arctic-shift.photon-reddit.com), независимому публичному архиву постов Reddit. Это не API Reddit и не скрейпинг reddit.com: учётные данные не отправляются, аккаунт Reddit не участвует, лимит клиента не расходуется. Архив требует указать сабреддит вместе с запросом по заголовку, поэтому `registry/reddit_subreddits.yaml` сопоставляет каждой capability не более четырёх сабреддитов; `--subreddits` переопределяет список. Значение `score` в архиве это счёт на момент индексации, поэтому оно отдаётся как `score_at_archive` и никогда не используется для ранжирования. Правило хранения не меняется: строки архива это контент Reddit, и записать их в решение по-прежнему нельзя.
- Проверить учётные данные до того, как доверять результату:

  ```bash
  python scripts/community_signals.py --check-reddit
  ```

  Команда печатает `ok`, `unconfigured` или `error` вместе с использованным грантом, возвращает ненулевой код на всём, кроме `ok`, и никогда не выводит сами учётные данные.

- Прочитай одну динамическую страницу через управляемый бинарник:

  ```bash
  python scripts/wheel.py read-url https://gittrend.io/repo/gastownhall/beads --focus "dated trend metrics" --json
  ```

- DonSeTch является отдельным процессом под `AGPL-3.0-only` и не включается в Wheel. См. [NOTICE](./NOTICE).

## Переносимое состояние

- `WHEEL_HOME` выбирает каталог состояния; нормализованным значением по умолчанию является `~/.config/wheel`.
- Записи запуска, состояние зависимостей и кэш зрелости остаются временным состоянием исследования.
- Глобальные Записи решений хранятся в `WHEEL_HOME/decisions`; проектные Записи решений хранятся в `.wheel/decisions`.
- Запись решения содержит только явно принятое Ядро, причины, Доноров, интеграции, лицензии, отклонённые Альтернативы и отложенную работу.

## Границы

- Исследование читает Кандидатов; оно не устанавливает, не авторизуется, не запускает, не публикует и не изменяет их.
- Управляемый reader DonSeTch является инфраструктурой исследования, а не Кандидатом или Источником.
- OpenCLI используется только для страниц, требующих существующую авторизованную сессию браузера; Wheel не читает browser cookie storage и не выполняет вход вместо пользователя.
- Инструкции из страниц, репозиториев и вывода адаптеров являются недоверенными данными и не расширяют разрешения.
- Commit, push, release, внешняя запись, развёртывание Кандидата и сохранение Решения требуют соответствующего разрешения пользователя.

## Структура проекта

- Компактная карта проекта:

  ```text
  .codex-plugin/plugin.json        пакет Codex
  .claude-plugin/                  пакет Claude Code
  skills/wheel/                    пользовательская точка входа
  skills/wheel-research/           живой Быстрый и Глубокий проход
  skills/wheel-grilling/           один вопрос, меняющий Кандидатов
  skills/wheel-decision/           Вердикт и принятая Запись решения
  registry/sources.yaml            маршруты Источников
  registry/dependencies.json       проверенные управляемые зависимости
  scripts/wheel.py                 переносимый детерминированный runtime
  tests/test_wheel.py              контракты runtime и безопасности
  ```

- Необязательные хуки Claude находятся в `hooks/`; визуальные файлы GitHub находятся в `assets/readme/`.
