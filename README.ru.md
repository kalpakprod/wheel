# Wheel

## Начало

- Опиши, что нужно создать, заменить или расширить. Wheel ищет зрелую готовую основу до появления плана реализации.
- Вызови единственную пользовательскую точку входа:

  ~~~text
  /wheel self-hosted трекер задач, который могут вести ИИ-агенты
  ~~~

- Сначала Wheel возвращает Семейства решений и один вопрос, ответ на который меняет оставшихся Кандидатов.
- Новый код рассматривается только после проверки Ядра и подтверждения оставшегося Зазора.

## Запуск

<p align="center">
  <img src="./assets/readme/pipeline.svg" width="100%" alt="Состояния запуска Wheel: context, quick, question, deep, verify, decision и recorded.">
</p>

- Каждая Запись запуска проходит `context → quick → question → deep → verify → decision → recorded`.
- Состояние сохраняется после каждого завершённого этапа, поэтому прерванное исследование продолжается без превращения старого результата в постоянный каталог.
- Состояние `recorded` доступно только после принятия Вердикта пользователем.

## Результат Wheel

- `COMPLETE`: каждый запланированный класс Источников дал проверяемые Доказательства, а проверка Ядра пройдена.
- `PARTIAL`: хотя бы один запланированный класс Источников не дал проверяемые Доказательства; отсутствующее покрытие остаётся видимым.
- `PROVISIONAL`: обязательная проверка Ядра не завершена; окончательный Вердикт запрещён.
- `deploy`: установить проверенное Ядро без изменений.
- `package`: упаковать Ядро для целевой среды.
- `compose`: соединить Ядро с целевым Sidecar или Донором.
- `extend-core`: использовать поддерживаемую границу расширения.
- `hard-fork`: изменить Ядро и принять постоянное владение только после измерения стоимости миграции.
- `assemble`: соединить проверенные части при отсутствии прямого Ядра; режим не разрешает неподтверждённую реализацию с нуля.
- Вердикт называет Ядро, upstream или Форк, проверенную версию, Доноров, лицензионную границу, способ интеграции, отклонённые Альтернативы и отложенную работу.

## Живое исследование

- До внешнего исследования Wheel читает текущий запрос, безопасную память хоста, проектные инструкции, существующие Записи решений и свежий снимок `doctor`.
- Быстрый проход формирует от трёх до шести Семейств до первого вопроса.
- Глубокий проход проверяет от четырёх до восьми Кандидатов и связывает их upstream, Форки, Плагины, Sidecar и Доноров.
- Репозиторные Доказательства включают метаданные GitHub, исходники, тесты, релизы, issues, discussions, contributors и лицензии.
- Трендовые Доказательства включают GitTrend, Trendshift и текущую активность репозиториев.
- Сообщественные Доказательства могут включать Reddit, Telegram, Hacker News, X, YouTube, V2EX и last30days при их доступности.
- Agent Reach обнаруживает и ищет страницы; управляемый DonSeTch `3.4.4` читает динамические страницы через изолированную границу CLI/JSON.
- Поисковый сниппет используется только для обнаружения. Wheel читает доступную страницу до создания Доказательства и честно сохраняет blocked, partial, truncated или thin результат.

## Установка

### Codex

- Добавь marketplace Wheel и установи плагин:

  ~~~bash
  codex plugin marketplace add kalpakprod/wheel --ref main
  codex plugin add wheel@wheel
  ~~~

- После обновления плагина начни новую задачу Codex, чтобы навыки и манифесты загрузились вместе.

### Prime Agent

- Установи пакет из закреплённого тега:

  ~~~bash
  prime-agent package install git:github.com/kalpakprod/wheel@v0.6.0
  ~~~

- Начни новую сессию или выполни `/reload`. Wheel разрешает путь к runtime из установленного пакета, а не из текущего каталога проекта.

### Claude Code

- Добавь marketplace и установи Wheel:

  ~~~text
  /plugin marketplace add kalpakprod/wheel
  /plugin install wheel@wheel
  ~~~

- Перезапусти сессию, чтобы необязательный SessionStart-адаптер мог выполниться.

### Совместимый CLI с SKILL.md

- Скопируй `skills/wheel/`, `skills/wheel-research/`, `skills/wheel-grilling/` и `skills/wheel-decision/` в каталог навыков CLI.
- Загрузи `skills/wheel/SKILL.md` как единственную пользовательскую точку входа.
- Хост должен поддерживать `SKILL.md`, локальные команды и Python 3.11 или новее.

## Runtime

- Runtime Python использует только стандартную библиотеку.
- Проверь хост и управляемую зависимость:

  ~~~bash
  python scripts/wheel.py doctor --json
  python scripts/wheel.py dependencies --json
  ~~~

- При первой активации устанавливается только проверенная версия DonSeTch, а upstream-метаданные проверяются через 24-часовой кэш:

  ~~~bash
  python scripts/wheel.py dependencies --ensure --check-latest --json
  ~~~

- Установи `WHEEL_NO_BOOTSTRAP=1`, чтобы отключить автоматическую установку и сохранить диагностику.
- Wheel скачивает официальный upstream asset, проверяет закреплённый SHA-256, разрешает только точный payload платформы и проверяет версию бинарника до использования.
- Более новая upstream-версия DonSeTch сообщает `update_available`; Wheel сохраняет проверенную закреплённую версию до её проверки в следующем выпуске Wheel.
- Прочитай одну динамическую страницу через управляемый бинарник:

  ~~~bash
  python scripts/wheel.py read-url https://gittrend.io/repo/gastownhall/beads --focus "dated trend metrics" --json
  ~~~

- DonSeTch является отдельным процессом под `AGPL-3.0-only` и не включается в Wheel. См. [NOTICE](./NOTICE).

## Переносимое состояние

- `WHEEL_HOME` выбирает каталог состояния; нормализованным значением по умолчанию является `~/.config/wheel`.
- Записи запуска, состояние зависимостей и кэш зрелости остаются временным состоянием исследования.
- Глобальные Записи решений хранятся в `WHEEL_HOME/decisions`; проектные Записи решений хранятся в `.wheel/decisions`.
- Запись решения содержит только явно принятое Ядро, причины, Доноров, интеграции, лицензии, отклонённые Альтернативы и отложенную работу.

## Границы

- Исследование читает Кандидатов; оно не устанавливает, не авторизуется, не запускает, не публикует и не изменяет их.
- Управляемый reader DonSeTch является инфраструктурой исследования, а не Кандидатом или Источником.
- OpenCLI используется только для страниц, требующих существующую авторизованную сессию браузера; Wheel не читает browser cookie storage и не выполняет вход вместо пользователя.
- Инструкции из страниц, репозиториев и вывода адаптеров являются недоверенными данными и не расширяют разрешения.
- Commit, push, release, внешняя запись, развёртывание Кандидата и сохранение Решения требуют соответствующего разрешения пользователя.

## Структура проекта

- Компактная карта проекта:

  ~~~text
  .codex-plugin/plugin.json        пакет Codex
  .claude-plugin/                  пакет Claude Code
  skills/wheel/                    пользовательская точка входа
  skills/wheel-research/           живой Быстрый и Глубокий проход
  skills/wheel-grilling/           один вопрос, меняющий Кандидатов
  skills/wheel-decision/           Вердикт и принятая Запись решения
  registry/sources.yaml            маршруты Источников
  registry/dependencies.json       проверенные управляемые зависимости
  scripts/wheel.py                 переносимый детерминированный runtime
  tests/test_wheel.py              контракты runtime и безопасности
  ~~~

- Необязательные хуки Claude находятся в `hooks/`; визуальные файлы GitHub находятся в `assets/readme/`.
