Плагин для Claude Code. Прежде чем агент напишет код, он ищет то, что уже делает эту работу, измеряет расстояние между найденным и твоей задачей и отвечает режимом внедрения, а не диффом.

Ты просишь добавить ретраи и расписание. Агент отвечает, что модуль, который ты хочешь расширить, и есть оркестратор workflow, что поддерживаемые оркестраторы уже существуют, и что несколько вопросов покажут, какой из них подходит под твои ограничения. Дальше он эти вопросы задаёт.

## Что он выдаёт

Шесть режимов, по возрастанию доли кода, которым ты в итоге владеешь:

| Режим | Что делаем | Кто владеет кодом |
| --- | --- | --- |
| `deploy` | ставим как есть | апстрим |
| `package` | упаковываем под свою среду | апстрим плюс наш образ или чарт |
| `compose` | берём один продукт, добавляем кусок другого | два апстрима плюс наш клей |
| `extend-core` | пишем расширение через его плагинный API | апстрим плюс наше расширение |
| `hard-fork` | правим ядро, теряем апстрим | мы, навсегда |
| `assemble` | прямого аналога нет, собираем из чужих кусков | мы, но по чужой архитектуре |

Седьмого режима под названием *пишем с нуля* не существует. Когда ничего не подошло, допрос продолжается, пока ответ не даст новый поисковый запрос, а результатом становится `assemble`: мёртвый репозиторий с хорошей архитектурой — это бесплатный проектный документ и легальный источник кода.

Дорогая граница проходит между `extend-core` и `hard-fork`. Первое сохраняет право тянуть обновления апстрима, второе его обрывает. Плагин обязан назвать, какой из двух предлагает и почему изменение не помещается в плагин или хук.

## Две оси, которые нельзя схлопывать

Зрелость отвечает на вопрос «можно ли на это опираться». Считается из GitHub API, а не из впечатления:

```console
$ node scripts/maturity.mjs kestra-io/kestra n8n-io/n8n oil-oil/beautify-github-readme
A  kestra-io/kestra                ★27812   deploy-gap:none   [alive adopted sustained safe bus]
B  n8n-io/n8n                      ★200711  deploy-gap:small  [alive adopted sustained bus]
A  oil-oil/beautify-github-readme  ★1605    deploy-gap:n/a    [alive adopted safe bus]
```

`n8n` получил `B`, потому что его лицензия fair-code, а не OSI. Такое лучше узнать до внедрения, чем после. Третья строка — репозиторий со скиллами: у него нет релизов и нечего разворачивать, поэтому он оценивается по четырём флагам вместо пяти.

Зазор отвечает на другой вопрос: сколько работы осталось.

| Зазор | Вопрос | Считается для |
| --- | --- | --- |
| функциональный | умеет ли нужное | всех кандидатов |
| операционный | разворачивается ли туда, куда надо | всех кандидатов, скриптом |
| архитектурный | лезет ли доработка в ядро | только двух финалистов |

У идеального софта, который ставится нативно, когда тебе нужен Kubernetes, функциональный зазор нулевой, а операционный стоит день работы. По одной лишь зрелости он выглядит как «просто поставь». Читать исходники шести проектов ради архитектурного зазора, когда пятеро отвалятся на первом вопросе, — причина, по которой это измерение ждёт финалистов.

## Как устроен допрос

<p align="center">
  <img src="./assets/readme/pipeline.svg" width="100%" alt="Шесть шагов конвейера: классификация задачи, инвентарь установленных скиллов, поиск на рынке вместе с допросом, измерение зрелости и зазоров, разделение бесплатных возможностей и будущих, вердикт одним из шести режимов внедрения.">
</p>

Вопросы вычисляются из того, чем кандидаты реально различаются. Задавать ли вопрос вообще, решает одно правило:

> Вопрос легален, только если его ответ убирает кандидатов.

Если при любом ответе остаются те же репозитории, вопрос про реализацию, а реализацию делает продукт, который ты внедряешь. Остаётся вот что:

```text
❓ Q1 — Вес: комбайн с UI и сотнями интеграций или движок без UI?

   комбайн → n8n, Windmill              (2 кандидата)
   движок  → Kestra, Prefect, Temporal  (3 кандидата)

➡️ Рекомендую движок: у тебя уже есть свой фронт, второй UI будет его дублировать.
```

Глубина обратна числу кандидатов. Восьмерым хватает одного раунда, потому что различия очевидны. Одному нужно три, потому что вопрос меняется с «который» на «этот ли вообще». Ноль кандидатов — случай, когда допрос становится длинным: каждая деталь ответа уходит новым запросом в смежную область, на другой язык, под другим названием той же задачи.

## Установка

```text
/plugin marketplace add kalpakprod/wheel
```

```text
/plugin install wheel@wheel
```

После этого перезапусти сессию: плагины подхватываются при старте.

## Использование

Гейт срабатывает сам через `SessionStart`-хук. Прямой вызов:

```text
/wheel оркестрация фоновых задач с ретраями
```

Оценить репозиторий, не запуская конвейер:

```bash
node scripts/maturity.mjs n8n-io/n8n kestra-io/kestra
node scripts/maturity.mjs --json owner/repo     # для скриптов
node scripts/maturity.mjs --self-check          # только логика, без сети
```

Результаты кэшируются в `registry/maturity.json` на семь дней. Нужен `gh` CLI с выполненным `gh auth login`.

Вердикты, которые стоит сохранить, пишутся в `~/.claude/wheel/decisions/`, и только когда выполнены все три условия: решение необратимо, неочевидно снаружи и стало результатом реального выбора. «Взяли Kestra вместо своего оркестратора» проходит. «Поставили форматтер» — нет.

## Каталог проектов

Шаг `S3` начинает поиск с каталога проектов, о которых говорят живые сообщества, поэтому первые кандидаты приходят уже разобранными: зрелость посчитана, стек и способ развёртывания записаны, термины ниши сохранены на русском и английском.

Каталог едет отдельно от плагина, из релизов [wheel-catalog](https://github.com/kalpakprod/wheel-catalog): он пересобирается каждые сутки, и коммитить его сюда означало бы заставить каждого, кто ставит плагин, качать эту историю. Проверка идёт фоном не чаще раза в сутки из того же `SessionStart`-хука, обходит зеркала из манифеста, сверяет архив с `sha256` и переставляет файл атомарно. Сети нет или каталога нет — шаг пропускается молча.

```bash
WHEEL_NO_UPDATE=1              # или {"autoupdate": false} в ~/.claude/wheel/config.json
scripts/catalog-update.sh      # обновить прямо сейчас
scripts/catalog-update.test.sh # пять проверок на двух подставных зеркалах
```

Оценок вида «стоит ли это ставить» в общем каталоге нет намеренно: они зависят от того, что уже есть в твоём стеке. Свой каталог, если ты его собираешь, кладётся в `~/.claude/wheel/catalog.local.jsonl` и читается первым.

## Чего он не делает

Плагин, созданный против лишнего кода, превращается в генератор переписываний, если его не удержать: замена твоего проекта всегда выглядит выгодно, потому что выигрыш от зрелого продукта большой и заметный, а цена миграции невидима, пока её не посчитали.

- Замена не предлагается без цифр: объём твоего кода, объём данных, число интеграций.
- Замена никогда не показывается в одиночку. Рядом стоит `extend`, и обе цены видны.
- Коду больше года и он в проде — замена переезжает из рекомендации в заметку.
- Взгляд вперёд делится надвое. Возможности, уже входящие в выбранный продукт, стоят ноль и предлагаются. Всё остальное записывается и остаётся непостроенным.

## На чём собран

Плагин, который требует брать готовое, обязан начать с себя.

| Что | Откуда | Зачем |
| --- | --- | --- |
| механика допроса | [mattpocock/skills](https://github.com/mattpocock/skills) | дерево решений, фронтир, раунды |
| когда решение стоит записи | оттуда же | необратимо, неочевидно, реальный выбор |
| установка скиллов под стек | [midudev/autoskills](https://github.com/midudev/autoskills) | детект технологий, установка нужных скиллов |
| дизайн-система README | [oil-oil/beautify-github-readme](https://github.com/oil-oil/beautify-github-readme) | project-native SVG, порядок содержания |
| правила текста | [anbeeld/WRITING.md](https://github.com/anbeeld/WRITING.md) | эта страница |

Оригинальные скиллы под MIT и форкнуты сюда как `wheel-grilling` и `wheel-decision`; что именно изменено, описано в [NOTICE](./NOTICE).

Своего осталось немного: правило отсечения, разделение риска и работы на две оси, `registry/capabilities.yaml` и скрипт зрелости.

## Структура

```text
.claude-plugin/plugin.json    манифест плагина
hooks/session-start.sh        инъекция гейта в каждую сессию
skills/wheel/SKILL.md         конвейер S0–S6
skills/wheel-grilling/        допрос
skills/wheel-decision/        запись вердикта
commands/wheel.md             /wheel
registry/capabilities.yaml    теги задач, скиллы, поисковые термины
scripts/maturity.mjs          пять флагов зрелости и операционный зазор
scripts/catalog-update.sh     фоновое обновление каталога, зеркала и sha256
```
