# Распространение каталога проектов

Дата: 2026-08-18. Статус: согласовано, к реализации.

## Запрос

Плагин `wheel` на шаге `S3` ищет кандидатов в `~/.claude/wheel/catalog.jsonl`. Сейчас этот
файл появляется только у автора: его собирает `curator` из телеграм-чатов на личной машине.
У всех, кто ставит плагин, шаг `S3` начинается сразу с GitHub Search, то есть самая ценная
часть гейта не работает.

Каталог обновляется ежедневно: новые сервисы выходят каждую неделю, и запись «о проекте
говорили в пяти разных сообществах за месяц» устаревает быстрее, чем выходит новая версия
плагина. Значит данные обязаны обновляться отдельно от кода и приезжать по сети.

## Решения

### Данные отдельно от кода

`kalpakprod/wheel` остаётся кодом плагина. Данные живут в `kalpakprod/wheel-catalog`,
где в `main` лежат только скрипты сборки и README. Сам каталог не коммитится: файл
переписывается целиком каждые сутки, и за год такая история весит гигабайты, которые
скачивает каждый, кто ставит плагин.

### Публичный слой против личного

Оценка `curator` устроена под конкретный профиль: `useful` отвечает на вопрос «чем полезно
именно ему», `tier` — «даёт ли то, чего нет в его стеке». Наружу такие поля уезжать не
должны, они введут в заблуждение чужого пользователя.

Публично: `slug`, `url`, `summary`, `problem`, `alt`, `keywords`, `stack`, `deploy`,
`selfhost`, `mode`, `gap_ops`, `risks`, `level`, `deploy_gap`, `stars`, `pushed_at`, `lang`,
`license`, `mentions`, `chats`.

Локально: те же поля плюс `useful`, `tier`, `verdict` — в `catalog.local.jsonl`, который
скилл грепает первым, когда он есть.

Цена решения: без `tier` у чужого пользователя пропадает ранжирование, и 8 000 карточек
становятся равнозначными. Компенсируют объективные сигналы — `chats` (в скольких разных
сообществах говорили), `mentions` и `level` зрелости.

### Доставка

Ежедневный релиз в `wheel-catalog`: тег по дате плюс скользящий `latest`.

Артефакты:

| Файл | Что внутри |
|---|---|
| `catalog.jsonl.gz` | публичный слой целиком, ~2,5 МБ сжато на ~10 МБ данных |
| `manifest.json` | `version`, `built_at`, `count`, `sha256`, `bytes`, `schema_v`, `mirrors[]` |

Зеркала в порядке обхода:

1. `github.com/kalpakprod/wheel-catalog/releases/latest/download/` — стабильный URL, CDN GitHub.
2. npm-пакет `@kalpakprod/wheel-catalog` — публикация даёт unpkg и jsDelivr бесплатно.
   Плагин ничего не устанавливает через npm, ходит на их CDN по HTTP.
3. `wheel.kalpak.dev` через уже поднятый Cloudflare Tunnel.

Целостность проверяется по `sha256` из манифеста, поэтому зеркало может быть любым.
jsDelivr раздаёт файлы по git-тегу, ассеты релизов — нет; проверить перед публикацией,
и если так, зеркало 2 держится на npm, а не на пути `gh/`.

### Клиент

Работа ложится в существующий `hooks/session-start.sh`. Он читает
`~/.claude/wheel/catalog.meta.json` и, если последняя проверка старше суток, запускает
`scripts/catalog-update.sh` фоном, не задерживая старт сессии.

Скрипт обновления: качает манифест (таймаут 5 с на зеркало, дальше следующее), сравнивает
`version` с локальной, при расхождении тянет архив, сверяет `sha256`, распаковывает во
временный файл и переставляет атомарно. Зависимости — `curl`, `gzip`, `sha256sum`
(на macOS `shasum -a 256`); `jq` не требуется, манифест разбирается через `sed`.

Выключается переменной `WHEEL_NO_UPDATE=1` или ключом в `~/.claude/wheel/config.json`.
Сети нет или все зеркала молчат — плагин работает на локальной копии; копии нет — источник
пропускается молча, как сейчас.

### Сборка

На homelab systemd-таймер раз в сутки: `poll → enrich → deepen → catchup → export` и
публикация (`gh release create`, `npm publish`, выкладка на сайт).

### Версия схемы

`schema_v` в манифесте. Скилл читает поля по имени и лишние игнорирует, поэтому рост
схемы не ломает старые установки плагина.

## Уже в коробке (включить?)

- `hooks/session-start.sh` существует, обновление вешается туда, новый хук не нужен.
- `registry/maturity.json` уже показывает, что данные едут вместе с плагином; тот же
  механизм проверки свежести применим и к нему.
- GitHub Releases считает загрузки: бесплатная статистика спроса на каталог.

## Придут позже (не строим)

- Шардирование по темам и дельта-обновления. При 2,5 МБ в сутки преждевременно;
  вернуться, когда каталог перевалит за 50 МБ.
- Приём чужих вкладов в каталог через PR.
- Публикация оценок `tier` под именем автора как отдельного курируемого слоя.
