# Управляемая зависимость DonSeTch

- Дата: 2026-08-31.
- Статус: реализовано и независимо проверено.
- Целевая версия Wheel: `0.6.0`.
- Проверенная версия DonSeTch: `3.4.4`.
- Стиль: Clausative 1.0.

## Назначение

- Wheel использует DonSeTch для чтения динамических страниц, которые обычный HTTP reader возвращает без проверяемого содержимого.
- Wheel устанавливает DonSeTch без предварительной глобальной настройки пользователя.
- Wheel проверяет происхождение, целостность и версию DonSeTch до исполнения.
- Wheel сохраняет независимость собственного MIT-кода от AGPL-кода DonSeTch.

## Канонические термины

- **Управляемая зависимость** обозначает отдельную программу, установленную Wheel в `WHEEL_HOME` и вызываемую через процессный интерфейс.
- **Проверенная версия** обозначает версию DonSeTch, с которой Wheel прошёл совместимые тесты.
- **Последняя версия upstream** обозначает текущий стабильный GitHub Release DonSeTch.
- **Манифест зависимости** обозначает детерминированный JSON-файл с версией, платформами, asset URL, SHA-256, лицензией и upstream.
- **Управляемый бинарник** обозначает DonSeTch из каталога версии в `WHEEL_HOME/dependencies/donsetch`.
- **Управляемый payload** обозначает Управляемый бинарник и точный набор обязательных runtime-файлов для одной платформы.
- **Адаптер DonSeTch** обозначает CLI/JSON-вызов управляемого бинарника.
- **Деградация маршрута** обозначает сохранённый статус Источника при отсутствии, несовместимости или ошибке DonSeTch.

## Архитектурное решение

- Wheel использует DonSeTch как отдельный Sidecar и не включает его код или бинарник в архив плагина.
- Wheel скачивает официальный release asset из `dondai44423/donsetch` непосредственно на машине пользователя.
- Wheel проверяет asset по SHA-256, закреплённому в Манифесте зависимости конкретного релиза Wheel.
- Wheel вызывает DonSeTch через CLI/JSON и не связывает его библиотеки с Python runtime Wheel.
- Wheel не использует глобальный npm-пакет или одноимённую команду из `PATH` как доверенную Управляемую зависимость.

## Лицензионная граница

- Wheel распространяется под MIT и не содержит производного кода DonSeTch.
- DonSeTch распространяется под `AGPL-3.0-only` как отдельная программа.
- Wheel сохраняет название, версию, лицензию, upstream и ссылку на исходный код DonSeTch в `NOTICE` и README.
- Wheel не модифицирует DonSeTch и не распространяет его release asset через репозиторий или релизы Wheel.
- Изменённая или самостоятельно распространяемая копия DonSeTch требует отдельного выполнения обязательств AGPL.
- Документ фиксирует инженерную границу и не заменяет юридическое заключение.

## Манифест зависимости

- `registry/dependencies.json` содержит одну запись DonSeTch.
- Запись содержит поля (`id`, `tested_version`, `source_repository`, `release_base_url`, `license`, `license_url`, `check_interval_seconds`, `platforms`).
- Каждая платформа содержит (`system`, `machine`, `asset`, `binary`, `required_files`, `sha256`).
- `required_files` содержит только basename обязательных обычных файлов из официального asset.
- Windows x86-64 требует (`donsetch.exe`, `pdfium.dll`), а Linux x86-64 требует (`donsetch`, `libonnxruntime.so`).
- Остальные поддерживаемые платформы требуют только Управляемый бинарник, пока upstream release workflow не добавит новый обязательный runtime-файл.
- Поддерживаемыми платформами являются (Windows x86-64, Linux x86-64, Linux ARM64, macOS x86-64, macOS ARM64).
- Неподдерживаемая платформа получает `unavailable` без попытки скачать другой asset.
- Манифест не содержит зеркал, токенов, параметров proxy или исполняемых команд из внешнего ответа.

## Каталог установки

- Корнем Управляемой зависимости является `WHEEL_HOME/dependencies/donsetch`.
- Версия устанавливается в отдельный каталог `WHEEL_HOME/dependencies/donsetch/<version>`.
- Исполняемый путь выводится только из Манифеста зависимости и текущей платформы.
- Глобальная команда `donsetch` не заменяет Управляемый бинарник и используется только как диагностический факт.
- Установка не изменяет глобальный npm, `PATH`, пользовательские shell profiles или конфигурацию MCP-хоста.

## Установка

- Команда `python scripts/wheel.py dependencies --ensure` устанавливает отсутствующую Проверенную версию.
- Команда скачивает asset во временный каталог под корнем версии.
- Команда ограничивает размер загрузки и использует HTTPS URL из Манифеста зависимости.
- Команда вычисляет SHA-256 локально и сравнивает его с Манифестом зависимости до распаковки.
- Несовпадение SHA-256 удаляет временный asset и завершает установку с ошибкой.
- Распаковка допускает только обычные файлы из `required_files` текущей платформы.
- Распаковка требует присутствие каждого `required_files` и запрещает отсутствующий, дублированный или дополнительный файл.
- Распаковка запрещает абсолютные пути, `..`, вложенные пути, symlink, hardlink и device.
- Готовый каталог версии публикуется атомарно после проверки бинарника.
- Команда запускает `donsetch --version` без shell и требует точное совпадение с Проверенной версией.
- Ошибка установки не блокирует Wheel и переводит зависимые маршруты в `unavailable` или `error`.

## Автоматическая активация

- Claude SessionStart выполняет `dependencies --ensure` до выдачи правила Wheel.
- Codex и совместимый generic CLI выполняют `dependencies --ensure` в начале пользовательского вызова Wheel.
- Автоматическая активация является первой переносимой точкой после установки плагина, поскольку общий install-hook отсутствует.
- `WHEEL_NO_BOOTSTRAP=1` отключает автоматическую установку и оставляет только диагностику.
- Автоматическая установка не принимает лицензию от имени пользователя молча: SessionStart и первый вызов сообщают название, версию, лицензию и upstream до первого скачивания.
- Повторный вызов не скачивает уже проверенную версию.

## Проверка версии

- `python scripts/wheel.py dependencies --json` возвращает локальную Проверенную версию, путь, checksum status и доступность.
- `python scripts/wheel.py dependencies --check-latest --json` дополнительно читает официальный latest release GitHub.
- Проверка latest release выполняется не чаще одного раза за 24 часа и сохраняет только публичные метаданные без credentials.
- Совпадение версий возвращает `current`.
- Более новая upstream-версия возвращает `update_available` и не заменяет Проверенную версию.
- Более старая или повреждённая локальная версия возвращает `repair_required`.
- Новая upstream-версия становится Проверенной только в следующем релизе Wheel после обновления Манифеста зависимости и тестов.
- Wheel не выполняет плавающее обновление `latest` во время исследования.

## Интеграция с doctor

- `wheel doctor --json` включает отдельную запись `donsetch-managed`.
- Запись содержит только (`status`, `path`, `version`, `tested_version`, `latest_version`, `checked_at`, `detail`).
- Запись не содержит stdout страницы, cookies, proxy, ключи или конфигурацию DonSeTch.
- Сломанный глобальный shim отражается отдельной диагностикой и не меняет статус Управляемого бинарника.
- Управляемый бинарник имеет приоритет над глобальной командой.

## Маршрутизация Источников

- GitTrend использует DonSeTch как основной Адаптер источника для чтения repository pages.
- Trendshift использует DonSeTch как основной Адаптер источника для чтения repository pages.
- Agent Reach сохраняет роль обнаружения URL и общего веб-поиска.
- Веб-класс и Документационный класс используют DonSeTch только при динамической странице, JS shell, bot wall или неполном обычном reader output.
- OpenCLI сохраняет роль чтения страницы через существующую пользовательскую браузерную сессию, когда требуется авторизованный контекст.
- DonSeTch не заменяет authenticated browser access, Reddit login state или platform-specific API.

## Контракт вызова

- Адаптер запускает `donsetch fetch <url> --json` без shell.
- Адаптер задаёт ограниченные (`deadline_ms`, `max_chars`, `focus`) из доверенной конфигурации Wheel.
- URL проходит существующую проверку Источника до передачи DonSeTch.
- stdout содержит JSON и разбирается отдельно от stderr.
- stderr сохраняется только как нечувствительная диагностическая категория.
- Результат считается читаемым только при корректном JSON, `content_ok=true` и содержательном извлечённом тексте.
- `content_ok=true` не подтверждает полноту страницы.
- Wheel сохраняет поля качества, способ получения и признаки (`quality`, escalation trace, adapter, truncation, pagination, thin content) при их наличии.
- Отсутствующая метрика, усечённый список или image-only output сохраняет `partial` и не подтверждает тренд.

## GitTrend

- GitTrend остаётся Источником трендового класса, а DonSeTch является только Адаптером источника.
- Адаптер читает repository page и извлекает датированные метрики, периоды, repository identity и trend placement.
- Страница без датированных метрик не подтверждает силу тренда.
- Доказательство GitTrend содержит точный URL, время чтения, извлечённую метрику и Кандидата.
- Live smoke-test использует публичную repository page и не меняет внешний сервис.

## Ошибки и деградация

- Отсутствующая Управляемая зависимость возвращает `unavailable` для DonSeTch-маршрута.
- Ошибка checksum возвращает `error` и запрещает исполнение скачанного файла.
- Неподдерживаемая платформа возвращает `unavailable` с названием платформы.
- Deadline возвращает `error` или `partial` в зависимости от сохранённого содержимого.
- Bot wall без доступного разрешения возвращает `blocked`.
- Captcha без явно настроенного upstream unlocker возвращает `blocked` и не запускает обходной платный путь.
- Ошибка одного DonSeTch-маршрута не изменяет статусы независимых Источников.
- Wheel не скрывает ошибку DonSeTch результатом Jina, OpenCLI или другого reader.

## Безопасность

- Установщик не исполняет shell, postinstall script или содержимое архива.
- Установщик не доверяет удалённому checksum-файлу вместо закреплённого SHA-256.
- Установщик не следует HTTP redirect на другой scheme или неожиданный host.
- Установщик проверяет конечный путь каждого файла до записи.
- Адаптер не передаёт DonSeTch credentials, browser cookie storage или значения secrets.
- DonSeTch cache и cookies остаются в собственной локальной области и не включаются в Записи запуска или решения.
- `DONSETCH_ALLOW_PRIVATE_EGRESS` не устанавливается Wheel.
- Wheel сохраняет default SSRF guard DonSeTch и собственную URL-валидацию.
- Автоматический paid unlocker, BYOK и proxy configuration не входят в интеграцию.

## Документация и благодарности

- README EN и README RU получают секцию `Dependencies and versions` с Проверенной версией, политикой обновления и командой диагностики.
- README EN и README RU получают отдельную секцию `Thanks` с перечислением фактически использованных проектов.
- Благодарности включают (DonSeTch, Agent Reach, last30days, OpenCLI, OpenExecutive, Clausative, mattpocock/skills).
- Каждая запись содержит роль проекта и ссылку на upstream.
- `NOTICE` содержит лицензионную атрибуцию DonSeTch и пояснение отдельной процессной интеграции.
- `LICENSE` Wheel остаётся MIT.

- Описание плагина сообщает о живом поиске и управляемом dynamic-page reader.

## Тестирование

- Unit-тест проверяет выбор asset для каждой поддерживаемой платформы.
- Unit-тест отклоняет неподдерживаемую платформу.
- Unit-тест отклоняет checksum mismatch.
- Unit-тест отклоняет archive traversal, symlink, hardlink, device, отсутствующий required file и неожиданный файл.
- Unit-тест принимает Windows и Linux x86-64 payload с точным набором companion runtime-файлов.
- Unit-тест подтверждает атомарную публикацию версии.
- Unit-тест подтверждает точный version output.
- Unit-тест подтверждает приоритет Управляемого бинарника над сломанным глобальным shim.
- Unit-тест подтверждает состояния (`missing`, `current`, `update_available`, `repair_required`, `unavailable`).
- Unit-тест подтверждает 24-часовой cache latest release.
- Unit-тест подтверждает раздельную обработку stdout и stderr DonSeTch.
- Unit-тест подтверждает, что `content_ok=true` без содержательных метрик не создаёт полное Доказательство GitTrend.
- Unit-тест подтверждает отсутствие secrets и внешних команд в JSON diagnostics.
- Валидаторы проверяют четыре навыка и Codex plugin manifest.
- Shell syntax, JSON, YAML, SVG, compileall, полный unittest и `git diff --check` входят в финальный gate.
- Опциональный live smoke-test выполняется только после локальной установки и не входит в CI.

## Критерии приёмки

- Новый пользователь получает Проверенную версию DonSeTch при первой активации Wheel без глобального npm.
- Проверка SHA-256 предшествует распаковке и исполнению.
- Wheel использует только Управляемый бинарник.
- GitTrend repository page читается через DonSeTch и возвращает датированное Доказательство либо честный неполный статус.
- Более новая upstream-версия обнаруживается и не устанавливается без нового Проверенного релиза Wheel.
- Отказ DonSeTch не блокирует независимые Источники Wheel.
- README EN и README RU сохраняют структурный паритет.
- README и `NOTICE` сообщают роль, upstream и AGPL-лицензию DonSeTch.
- Архив Wheel не содержит DonSeTch binary, source или cache.
- Плагин остаётся переносимым между Codex, Claude Code и generic SKILL.md CLI.

## Не входит в реализацию

- Wheel не модифицирует DonSeTch.
- Wheel не запускает DonSeTch как постоянный общий MCP server.
- Wheel не управляет browser login, cookies, proxy, BYOK или paid unlocker DonSeTch.
- Wheel не гарантирует обход captcha или platform authentication.
- Wheel не устанавливает последнюю непроверенную upstream-версию.
- Wheel не заменяет Agent Reach, last30days, OpenCLI или platform-specific adapters.
