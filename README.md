# wheel

Плагин для Claude Code: **колесо уже изобретено**. Перед тем как написать строчку кода, агент ищет готовое решение на рынке, измеряет расстояние между ним и твоей задачей, допрашивает тебя вопросами, вытащенными из различий между кандидатами, и выдаёт режим внедрения — а не новый код.

Вердикта «пишем с нуля» в системе нет. Худший исход называется `assemble` — сборка из чужих кусков и ориентиров.

## Зачем

Код, написанный с нуля, надо ревьюить, тестировать, чинить и поддерживать. Зрелый репозиторий с тысячами звёзд всё это уже прошёл на чужие деньги. Разница между «написать оркестратор» и «поднять Kestra» — это не разница в неделях, это разница между владением кодом и владением конфигом.

Чем зрелее проект, тем прямее он идёт в прод. Плагин делает эту оценку измеримой, а не интуитивной.

## Главный сценарий

Ты: «добавь в мой сервис ретраи и расписание запусков»

Агент (до единой строчки кода):
> Стоп. У тебя в проекте 2 400 строк, которые повторяют оркестратор workflow. Нашёл 5 кандидатов. Прежде чем добавлять ретраи — три вопроса, каждый режет список пополам:
>
> ❓ **Q1 — Вес:** комбайн с UI и 400 интеграций или движок без UI?
> ➡️ Рекомендую движок: у тебя уже свой фронт, UI будет дублировать.

И дальше — таблица режимов с ценой каждого, включая честную цену замены твоего кода.

## Конвейер

| Шаг | Что делает |
|---|---|
| `S0` | классификация: greenfield / фича в существующее / замена + теги задачи |
| `S1` | инвентарь: какие скиллы и плагины у тебя уже есть, что включить прямо сейчас |
| `S2` | грилинг: вопросы, вытащенные из различий между кандидатами |
| `S3` | рынок: своя база → реестр софта → GitHub → awesome-списки → веб |
| `S4` | зазоры × зрелость → режим внедрения |
| `S5` | forward-look: что достаётся даром и что придёт позже |
| `S6` | вердикт + запись в базу знаний по критерию ADR |

`S2` и `S3` идут внахлёст: первый проход поиска даёт материал для точных вопросов, ответы дают новые запросы.

## Две оси, которые нельзя смешивать

**Зрелость** отвечает на «можно ли на это опираться». Пять флагов, считаются скриптом из GitHub API: `alive` (пуш меньше 90 дней назад), `adopted` (500+ звёзд), `sustained` (2+ релиза за год), `safe` (OSI-лицензия, не архив), `bus` (3+ контрибьютора).

```
A  kestra-io/kestra  ★27812  deploy-gap:none  [alive adopted sustained safe bus]
B  n8n-io/n8n        ★200711 deploy-gap:small [alive adopted sustained bus]
```

`n8n` получил `B` не по ошибке: у него fair-code лицензия, не OSI. Это ровно тот факт, который стоит узнать до внедрения, а не после.

**Зазор** отвечает на «сколько нам работы». Три штуки:

| Зазор | Вопрос | Считается |
|---|---|---|
| функциональный | умеет ли нужное | для всех кандидатов |
| операционный | разворачивается ли куда надо | для всех кандидатов (скриптом) |
| архитектурный | лезет ли доработка в ядро | только для двух финалистов |

Идеальный софт, который ставится только нативно, а нужен в k8s — это `deploy-gap: large`, то есть день работы. По одной лишь зрелости он выглядел бы как «просто поставь».

## Режимы внедрения

| Режим | Что делаем | Кто владеет кодом |
|---|---|---|
| `deploy` | ставим как есть | апстрим |
| `package` | упаковываем под свою среду | апстрим + наш образ/чарт |
| `compose` | берём основной, вкладываем кусок другого | два апстрима + наш клей |
| `extend-core` | пишем расширение через плагин/хук | апстрим + наше расширение |
| `hard-fork` | правим ядро, апстрим теряем | наше целиком |
| `assemble` | прямого аналога нет, собираем из кусков | наше, на чужих ориентирах |

Граница `extend-core` / `hard-fork` — самая дорогая в таблице: первое сохраняет право тянуть обновления, второе обрывает его навсегда. Агент обязан назвать, какой из двух предлагает и почему.

## Предохранители

Плагин против лишнего кода легко превращается в генератор переписываний — совет «выброси своё, возьми чужое» всегда выглядит выгодно, потому что цена миграции невидима, пока не посчитана. Поэтому:

- замена не предлагается без цифр: объём своего кода, объём данных, число интеграций;
- замена всегда показывается рядом с `extend`, никогда в одиночку;
- своему коду больше года и он в проде — замена уходит в «к рассмотрению», а не в рекомендацию;
- forward-look делится на «уже в коробке, включить?» (стоит ноль) и «придёт позже» (не строим ни строчки);
- ноль кандидатов не означает «пиши сам» — означает, что грилинг продолжается.

## Установка

```text
/plugin marketplace add kalpakprod/wheel
```

```text
/plugin install wheel@wheel
```

Затем перезапусти сессию — плагины подхватываются при старте.

## Использование

Гейт работает сам через SessionStart-хук. Явный вызов:

```text
/wheel оркестрация фоновых задач с ретраями
```

Оценка кандидата вручную:

```bash
node scripts/maturity.mjs n8n-io/n8n kestra-io/kestra
node scripts/maturity.mjs --json owner/repo    # для скриптов
node scripts/maturity.mjs --self-check         # проверка логики без сети
```

Результаты кэшируются в `registry/maturity.json` на 7 дней. Нужен `gh` CLI с `gh auth login`.

## Что взято готовым

Плагин, который требует брать готовое, обязан начинать с себя:

| Что | Откуда | Зачем |
|---|---|---|
| механика допроса | [mattpocock/skills](https://github.com/mattpocock/skills) → `grilling` | дерево решений, фронтир, раунды |
| критерий записи решения | там же → `domain-modeling` | правило ADR: необратимо + неочевидно + реальный выбор |
| установка скиллов под стек | [midudev/autoskills](https://github.com/midudev/autoskills) | детект технологий → скиллы |
| философия | [ponytail](https://github.com/dietrichgebert/ponytail) | лучший код — тот, который не написали |

Своего здесь немного: правило отсечения вопросов, две оси вместо одной шкалы, `capabilities.yaml`, скрипт зрелости и склейка.

## Структура

```text
.claude-plugin/plugin.json   манифест плагина
hooks/session-start.sh       инъекция гейта в каждую сессию
skills/wheel/SKILL.md        конвейер S0–S6
commands/wheel.md            /wheel
registry/capabilities.yaml   intent → скиллы и поисковые термины
registry/maturity.json       кэш оценок (создаётся при первом запуске)
scripts/maturity.mjs         5 флагов зрелости + операционный зазор
```
